# Security policy

## Supported versions

Security fixes target the current `main` branch and the current production
release. Older snapshots, retired implementations and experimental worktrees
are not maintained as separate supported releases.

## Reporting a vulnerability

Report vulnerabilities privately using [GitHub private vulnerability reporting](https://github.com/Paul1404/diatrack/security/advisories/new).
Do not open a public issue or discussion with security details.

Include the affected component, version or commit, impact, and the smallest
reproduction using synthetic data or an isolated test account. Explain whether
the issue affects a self-hosted installation or the maintained deployment.

Do not include credentials, tokens, production exports, or personal, health,
financial or customer records. Do not access another person's data, disrupt
availability, or change production financial or marketplace state while testing.
Stop if testing exposes unexpected access, and describe the observation privately.

Maintainers will review the report privately and coordinate a fix and disclosure.
